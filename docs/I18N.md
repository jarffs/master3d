# Labels and Translations

The active catalogs are `locales/en.json` and `locales/pt.json`. Run `npm run test:i18n` for translation regressions and `npm run build` for the production bundle.

## Conventions

- Use `t('namespace.key', { name: value })` for dynamic messages. Both catalogs must have the same keys and interpolation parameters.
- Mark static text with `data-i18n`. Put the attribute on a text span when a button also contains icons.
- Use `data-i18n-placeholder`, `data-i18n-title`, `data-i18n-aria-label`, and `data-i18n-alt` for attributes.
- When a modal changes mode, update its translation key along with its visible text.
- Never attach translation keys to user-entered names or file names. Default layer names may use `layerTranslationKey`; custom names remain unchanged.
- ControlBuilder marks labels, descriptions, categories, options and placeholders for live translation. Changing language must not reset input values or non-language selects.
- Invalid saved languages fall back to the browser's supported language, then English. Missing entries fall back to English. Missing keys in both catalogs remain visible as keys and fail the coverage test.

## Verified Scope

- Catalog parity, nonempty referenced entries and matching interpolation parameters.
- Literal translation keys in active source files and categories in generator schemas.
- Labels and value preservation across PT/EN switches for all seven generators.
- Unmarked prose in the active index, app and hub HTML, excluding brands, contact addresses and language-independent values.
- Live landing page, hub, stamp, keychain and big-letter pages, including registration titles and desktop/mobile screenshots.
- Translated alerts for uploads, exports, projects, authentication and checkout; these checks do not execute paid transactions.

Historical `app_backup.html` and `app_main.html`, patch scripts and demo files are not published entry points and are not part of the page audit. The disabled advanced-vectorization comparison dialog is not part of the active-page audit. User content, font/printer names and raw third-party service error messages are not translated automatically. Static scans cannot prove the language of every dynamically constructed string; browser regressions cover the listed flows.

## Fixed Causes

Missing big-letter and authentication keys, untranslated hub/panel text, ignored placeholder attributes, invalid persisted language, stale modal keys, non-language select values being overwritten, and optional descriptions throwing in the translator.
